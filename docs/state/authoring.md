# Create a readable state map

Nessa Docs turns source-grounded Markdown into a browsable map of what a project does. The skill writes the Markdown in the target repository; a separately installed renderer displays it.

For example, a payment flow should show who accepts a request, which outcomes are refused or uncertain, and which source owns each decision. A component map explains cooperating parts; it should not pretend every box is one exclusive application state.

The [packaged skill](../../skills/nessa/nessa-docs/SKILL.md) owns the workflow and its [format reference](../../skills/nessa/nessa-docs/references/format.md) owns metadata, diagram navigation, details and optional model records. Read the actual target code and preserve a per-page source checkpoint. A checkpoint says what was inspected, not that a test ran.

A risky flow can have a bounded TLA+ model. The canonical checker executes the authored model, not the target implementation. A stopped or unfinished rule is unchecked. Catalog validation checks structure and linked files; it is not a rule check. Keep saved checker results generated by the checker.

## Distribution boundary

This repository packages its own copy of the Nessa Docs authoring skill. The renderer repository also maintains a skill at `nessalabs/nessa-docs/skills/nessa-docs`. They can differ at a given source revision; installing one does not update the other. This page describes the packaged copy at its checkpoint, not an unmerged proposal or automatically synchronized upstream content.

The MCP path publishes complete snapshots with revision checks. A conflicted replacement must be reconciled from the current snapshot rather than overwritten. Memory-mode bundles are session-only; configured durable storage is an explicit separate boundary. The host supplies documents and chooses what tools exist. No MCP server runs in this skills repository.
