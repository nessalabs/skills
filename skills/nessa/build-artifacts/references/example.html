Decision brief

Example brief: should Acme Notes add offline sync?

A sample brief about a made-up app, written to show every component. The answer: build offline sync for one device first, and skip real-time collaboration.

  • Nov 27, 2026
  • Sample content

The short version

Acme Notes loses edits when the laptop goes offline, and that is the top complaint in the sample support log. The app already saves every edit locally, so the missing piece is sending those saved edits once the connection is back.

RecommendationJudgment

Build offline sync for one person on one device first. It fixes the top complaint with pieces the app already has. Leave real-time collaboration for later.

What to do first

Judgment Ranked by what fixes the most for the least work.

  1. Stop dropping queued edits. The queue gives up after 3 tries, so a long trip offline loses work. Keep items until the server accepts them.
  2. Send edits in the order they were made. Without this, an old edit can overwrite a newer one.
  3. Show what is still waiting. A small "3 edits not sent yet" line tells people their work is safe.
  4. Measure how often two devices clash. That number decides whether collaboration is worth building.

Ideas

Judgment Sample ideas. Each card has the same parts in the same order.

Sync status line

Judgment
Pitch
A quiet line at the bottom that says how many edits are waiting to be sent.
Who it's for
Anyone who works on trains or planes.
Why we win
The local database already knows what is unsent.
Smallest first version
A count and a "Send now" button.
Risks
People may worry more when they see a number.

Conflict copy

Judgment
Pitch
When two devices clash, keep both versions side by side instead of picking one.
Who it's for
People who edit the same note on a phone and a laptop.
Why we win
It needs no merge logic, only a second copy.
Smallest first version
Save the losing edit as "Note (conflict copy)".
Risks
Too many copies if clashes are common.

Offline notice

Judgment
Pitch
Say plainly when the app is offline, so nobody is surprised later.
Who it's for
People who don't notice when the connection drops.
Why we win
The app already checks the connection before each save.
Smallest first version
The word "Offline" in grey next to the note title.
Risks
A notice that flickers on a weak connection is worse than none.

What must always hold

  1. An edit is never removed from the queue until the server has accepted it.
  2. Edits to one note reach the server in the order they were made.
  3. Sending the same edit twice changes the note once.

What to skip

Judgment

  • Building our own sync protocol. Use the server's existing save call.
  • Real-time cursors and presence. They do not fix the top complaint.

Risks and open questions

Judgment

Risks

  • A very long queue could make the first sync after a trip slow.
  • Users on old app versions will still drop edits until they update.

Open questions

  • How many users edit on more than one device? This decides the next step.
  • Should the "Send now" button exist, or should sending always be automatic?
